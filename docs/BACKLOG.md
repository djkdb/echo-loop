# Echo Loop — 백로그

지금 마일스톤 범위 밖이라 미뤄 둔 결정·개선, 구현하면서 드러난 한계. 해당 시점이 오면 여기서 꺼내 판단한다.

## 퍼즐 설계

- ~~패러독스가 자연 발생하려면 "닫는" 요소가 필요하다.~~ → **해결(phase-a)**: 반전 문(`Door.inverted`) + 레버.
  `levels/level_test_paradox`에서 "레버를 먼저 당기면 문지기가 붕괴"가 실제로 일어난다.
  - 1-5 "막지 마라" 본 레벨 설계는 아직. 이 테스트 방의 구조(레버 → 반전 문 → 판 → 문)를 출발점으로 쓴다.
- ~~레이저 vs 2-3 "방패" 충돌.~~ → **결정(phase-b 전): (a)** 고스트는 빔을 막고 붕괴하지 않으며 빔은 고스트에서 끝난다.
  Player가 닿으면 루프 실패. `tests/cases/test_12_laser.gd`로 검증.
- **파랑 문(고스트만 통과)의 의미.** 고스트는 과거의 나의 경로라, 지금의 내가 못 지나가는 파랑 문을 고스트가 지나가는 일은
  "녹화 때는 열려 있다가(신호) 지금은 닫힌" 경우에만 생긴다. 2-5 "파랑과 주황"은 신호로 여닫는 색 문으로 설계해야 한다.

## 오브젝트 한계

- **상자**: 옆면은 충돌이 없고 위치 규칙으로 밀린다(결정론을 위해). 그래서
  - 상자가 벽에 막힌 채 계속 밀면 Player가 상자 속으로 들어간다(보이는 문제, 판정은 정상).
  - 상자끼리는 서로 밀지 않는다(one-way 옆면을 통과). 한 방에 상자 1개 기준.
  - 떨어지는 상자는 몸을 통과한다(mask = world).
- **이동 발판**: 몸을 지형 쪽으로 짓누르게 되면 그 틱은 멈춘다(엘리베이터 안전장치). 짓눌러 탈락시키는 퍼즐은 없다.
  상자는 끼임 판정 대상이 아니다.
- **색 문은 레이저를 막지 않는다**(빔은 world만 본다).

## 비주얼

- **캐릭터를 약 2배 크게 보이게 하기(phase-b에서 건너뜀).** 방 내부가 이미 화면 너비의 89%(640/720)를 써서
  카메라 줌만으로는 방이 화면을 넘는다. 2배로 보이려면 월드 스케일을 바꿔야 한다:
  (a) 레벨 기하를 절반 크기로 다시 짜고 카메라 2배 줌 — 몸(40×64)·점프(176px)·이동(360px/s)은 그대로라
      방 대비 점프가 2배로 커져 모든 레벨을 다시 맞춰야 한다.
  (b) 몸·속도·점프·중력·발판·상자 수치를 전부 절반으로 하고 레벨도 절반 + 2배 줌 — 화면상 느낌은 같지만
      게임 로직 수치와 자동 테스트 좌표를 전부 바꿔야 한다.
  phase-b 지시("게임 로직은 건드리지 않는다")와 충돌해 보류. 스테이지 제작(타일 크기 결정) 전에 (a)/(b) 결정.
  레벨 배치 규칙의 y 좌표(240~440 등)는 이 결정 뒤에 갱신한다.
- **클리어 리플레이 2배속**: Engine.time_scale은 물리 delta를 바꿔 상자 낙하 등 재생 결과가 달라진다.
  지금은 실시간으로 렌더하고 편집에서 배속(ffmpeg `setpts=0.5*PTS`)하는 쪽을 권장.
