# Echo Loop — 백로그

지금 마일스톤 범위 밖이라 미뤄 둔 결정·개선, 구현하면서 드러난 한계. 해당 시점이 오면 여기서 꺼내 판단한다.
위쪽이 열린 항목, 맨 아래는 해결된 항목의 기록이다.

## 퍼즐·레벨

- **최소 고스트 수의 근거는 설계 노트다.** 자동 테스트(`test_70~72`)는 "정답이 재현되고 CLEAR된다"와 "정답에서 루프 하나를
  빼면 CLEAR되지 않는다"까지만 본다. 다른 풀이로 기록보다 적게 깨는 방법이 없다는 건 `docs/levels.md`의 높이·칸·문 간격 근거로
  보장한다. 플레이 테스트에서 더 적은 풀이가 나오면 그 레벨 배치를 고치거나 기록(★3 기준)을 내린다.
- **기록 = 상한인 스테이지는 ★2 구간이 없다**(1-1~1-5, 2-2, 2-4, 3-1, 3-2). 상한을 1 올리면 ★1/★3 사이가 생기지만
  기획서 상한을 따랐다. 플레이 테스트 뒤 결정.
- **개별 재녹화(1~4)를 꼭 써야 하는 스테이지가 없다.** 지금은 실수를 고치는 도구로만 쓰인다.
- **첫 스테이지 안내 문구가 없다.** 1-1에서 "R로 루프 끝내기", "과거의 나를 밟아 보세요" 같은 한 줄 힌트를 HUD 릴스 텍스트 자리에
  띄우는 것을 검토(플레이 테스트 기준: 5분 안에 못 풀면 힌트).
- **2-1 발판은 꼭대기에서 멈추지 않고 바로 내려간다.** 선반 옆면에 붙어 있다가 올라서야 한다(봇은 꼭대기 40px 전부터 왼쪽을
  누른다). 어렵다는 반응이 나오면 MovingPlatform에 양 끝 대기 시간을 넣는다.

## 오브젝트·물리 한계

- **상자**: 옆면은 충돌이 없고 위치 규칙으로 밀린다(결정론을 위해). 그래서
  - 상자가 벽에 막힌 채 계속 밀면 Player가 상자 속으로 들어간다(보이는 문제, 판정은 정상).
  - 상자끼리는 서로 밀지 않는다(one-way 옆면을 통과). 한 방에 상자 1개 기준.
  - 떨어지는 상자는 몸을 통과한다(mask = world).
- **이동 발판**: 몸을 지형 쪽으로 짓누르게 되면 그 틱은 멈춘다(엘리베이터 안전장치). 짓눌러 탈락시키는 퍼즐은 없다.
  상자는 끼임 판정 대상이 아니다.
- **색 문은 레이저를 막지 않는다**(빔은 world·고스트만 본다).
- **구멍 폭**: 몸(40)보다 12px 이상 넓어야 걸어서 지나갈 때 빠진다(6px/틱). 45px 구멍은 달리면 건너가 버린다. 지금 레벨은 50~60px.

## 비주얼·연출

- **클리어 리플레이 2배속**: Engine.time_scale은 물리 delta를 바꿔 상자 낙하 등 재생 결과가 달라진다.
  지금은 실시간으로 렌더하고 편집에서 배속(ffmpeg `setpts=0.5*PTS`)하는 쪽을 권장.
- **고스트·발판·상자가 위로 움직일 때 위에 선 Player 발밑을 파고든다(고스트 점프 기준 최대 15px).**
  sync_to_physics 바디의 이동은 물리 스텝에 반영되고 Player는 그 플랫폼 속도를 다음 틱에 받는 엔진 구조상 1틱 지연이 있다.
  위치 재생·결정론에는 영향 없음.
- **1-3 출구 아치가 천장에 10px 겹쳐 그려진다**(턱 높이 270을 지키려고). 에디터에서 출구 그림을 줄이거나 턱 높이를 다시 잡는다.

## 모바일·배포

- **모바일에는 되돌리기(Backspace)·처음부터(Shift+R) 버튼이 없다.** C4 범위(이동·점프·E·고스트 탭·시간 바 길게)만 넣었다.
  필요하면 HUD 오른쪽 위 ≡ 옆에 추가.
- **itch.io 업로드는 사람이 한다**: `build/web` 폴더를 zip → itch.io "HTML" 프로젝트 → "This file will be played in the browser",
  뷰포트 720×1280(또는 360×640) 세로. 스레드를 끈 빌드라 SharedArrayBuffer 설정은 필요 없다.

## 촬영

- **붕괴 장면 촬영용 디버그 키**(고스트 강제 붕괴 등): 릴스 촬영 시점에 검토. 입력 액션이 새로 필요하다.

## 해결된 항목 (기록)

- 패러독스 요소 → 반전 문 + 레버(phase-a). 1-5 "막지 마라"가 이 구조를 두 층으로 쓴다(phase-c).
- 레이저 vs 2-3 "방패" → (a) 고스트는 빔을 막고 붕괴하지 않는다(phase-b 전). 발사구 위에 선 고스트도 막도록 고침(phase-c).
- 파랑 문의 의미 → 2-5에서 "판이 눌리면 닫히는 파랑 문": 먼저 녹화한 고스트는 닫힌 뒤에도 지나간다(phase-c).
- 고스트 점프 부스트 → 움직이는 고스트 위 점프 불가 + 플랫폼 속도 물려받지 않음(phase-c, CLAUDE.md 규칙 13).
  올라타기 점프를 기술로 살리고 싶어지면 이 규칙을 끄고 높이 퍼즐(1-1, 1-3, 2-2, 3-2, 3-3, 3-5) 최소 고스트 수를 다시 잡는다.
- 캐릭터 2배 → (a) 레벨 기하를 작게 + 카메라 줌(phase-c C0). `level_test`(유닛 테스트 샌드박스)는 큰 방으로 남겼다.
- 시작하자마자 CLEAR(원점 근처 출구의 낡은 겹침) → Player를 방 밖에서 시작(phase-c).
- 공중의 고스트가 내려앉으며 Player를 짓누름(벽 속으로 밀려남) → 짓눌린 Player = 루프 실패(phase-d D3).
  몸을 가로 8·세로 17px 줄인 사각형이 지형·고스트와 겹치면 짓눌림(올라탄 고스트의 1틱 파고듦 15px은 제외, 상자 제외).
  고스트가 벽 쪽으로 걸어와 Player를 밀어붙이는 것도 짓눌림이다.
- 폰트 서브셋 4.8MB → 358KB(`tools/subset_font.py`, phase-c C5).
- 자동 테스트 저장소 안으로(`tests/run_all.gd`), 웹 내보내기에서 `tests/* solutions/* tools/* docs/* build/*` 제외(C5).
